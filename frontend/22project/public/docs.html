使用与维护说明

东风设备轴承故障诊断
模型管理平台

把「轴承振动数据 → 训练模型 → 模型产物 → 在线推理 → 落库 → Web 展示」串成一条能真跑通的流水线。 侧重点不是单个模型的精度上限，而是这条链路的完整性与可追溯性： 训练出来的模型能推理、推理结果能查到逐样本明细、每个模型的参数都能在页面上看到。

后端 Flask + Flask-RESTful 前端 Vue 3 + Vite + Element Plus 数据库 MySQL 8 / 9 模型 3 套 业务接口 28 条 数据表 11 张

01这是什么

一套面向实验室 / 工厂内网的模型管理平台。它要解决的是一个具体问题： 原始训练脚本跑完就把模型丢在内存里——仓库里没有权重文件、没有推理入口、数据库里一张表都没被写过， 那条件链是断的。本平台把断点补上，并且保证每一环都能被验证。

一句话概括：把「脚本跑完就散」的过程，变成一条有账号、有数据、有产物、有记录、能交付的线。 平台只有两种身份——管理员与普通用户：日常干活（训练、推理、发布、 删产物、看图）两种身份都能做，管理员多出用户管理与操作日志两项， 并且能把普通用户设为管理员、或停用某个账号（详见 10 登录与会话）。

为什么是两层接口

前端基于 django-vue3-admin 模板，它的 axios 拦截器强制校验 {code, data, msg} 信封； 而业务接口按 REST 惯例返回裸 JSON。硬拧在一起会出现「页面能开但所有数据为空、控制台报 非标准返回」。于是拆成两层，互不污染：

层文件返回形状覆盖什么
业务接口 model_service/api.py 裸 JSON 模型、数据集、训练、推理、发布、图、系统信息（28 条）
dvadmin 兼容层 model_service/dvadmin.py {code,data,msg} 信封 登录、动态菜单、用户与用户管理、操作日志、字典、设置、部门、SSE 桩
前端对应实例 utils/platformRequest.ts / utils/request.ts — 前者绕开信封校验，后者走框架默认逻辑
路由注册顺序不能改

main.py 里的顺序是：兼容层 → 业务接口 → 前端托管。 最后那个 SPA 兜底 /<path:path> 是无差别匹配，注册早了会把 /health、/models 一起吃掉、统一返回 index.html。 Flask 按注册顺序匹配，所以最后注册 = 优先级最低。

adtk 这条最容易踩坑

PcaAD 内部是 PcaReconstructionError(k) + InterQuartileRangeAD(c)， 它把 DataFrame 的每一行当成高维空间里的一个点。所以必须喂 「行 = 一个窗口」的矩阵；如果按「采样点 × 1 列」喂，PCA 会退化成 1 维、 重构误差恒为 0，判出来的"异常"与故障完全无关。

判定阈值 threshold0.001588
基线误报率0.0

meta.json 里有什么

这是模型的"身份证"——判断一份产物能不能用、怎么用，看它。字段如下：

字段含义
model / task / framework内部键、任务类型（分类/异常检测）、框架标识
weights_file / scaler_file权重文件名、标准化参数文件名（推理必须一起用）
input_len / num_classes / labels输入窗口长度、类别数、类别顺序表（class_id → 中文标签）
params本次训练的全部超参（上表那些就来自这里）
metrics测试/验证指标、逐轮 history、混淆矩阵，以及 untested_labels（见 §13）
dataset数据集名、路径与切窗统计（含越界被跳过的窗口数）
provenance / trusted来源信息；trusted=false 表示这是上传的产物，推理侧不会反序列化它的 .pkl
trained_at / created_at / log_file训练时间、落盘时间、对应的训练日志文件

切窗策略：越界就拒绝，不补 NaN

每个文件被切成若干个 length=784、步长 150 的窗口。 原始脚本会把越界的那一段补成整行 NaN； 服务侧改成拒绝并回报（strict=true）：越界窗口被跳过并计数， 数字写进训练记录的 Remark 与产物的 metrics。 这样做的好处是"指标不好看"能一眼看出是数据不够，而不是被 NaN 悄悄污染。

IR014 点数不足（数据本身的问题，不是 Bug）

IR014 只有 63,788 点（其它文件约 24 万点）， 而默认参数（length=784, number=600, stride=150）需要切到 91,418 点。 于是该类180 个测试窗全部越界被跳过，这一类不参与指标计算 ——产物 metrics.untested_labels 里会显式列出来（当前值为「内圈故障-0.014in」）。 只看 accuracy 而不看这个字段，会高估模型的真实表现。

05一条完整链路

下面五步就是平台的核心闭环，每一环都会落库。命令示例统一用 curl（Windows 上写 curl.exe）。

  1. 选模型与数据集，发起训练 「模型管理 → 训练」或直接调接口。需 train:run 权限 
    curl.exe -X POST http://127.0.0.1:5000/train -H "Authorization: Bearer <令牌>" -H "Content-Type: application/json" -d "{\"model\":\"1dcnn\",\"dataset_dir\":\"1DCNN/0HP\"}"
    dataset_dir 用工作区相对路径（1DCNN/0HP），后端按「工作区 → 项目目录」顺序解析。 训练走完「切窗 → 标准化 → 训练 → 评估 → 出图」，写一条 Trainings（失败也写一行）。
    注意 /train 是同步阻塞的，本项目不做排队。
  2. 产物落盘（一个模型一份） 写到 data/models/<模型名>/：权重 + scaler.npz + meta.json。 没有版本号——重训/重传就是直接替换那一份；旧版本被搬到 data/archive/model_versions/ 留底（不入库）。 这样"当前模型"与"历史训练记录"是两件事，不会越滚越多。
  3. 推理 需 predict:run 权限 
    curl.exe -X POST http://127.0.0.1:5000/predict -H "Authorization: Bearer <令牌>" -H "Content-Type: application/json" -d "{\"model\":\"1dcnn\",\"path\":\"1DCNN/0HP/48k_Drive_End_IR007_0_109.mat\",\"index\":0,\"limit\":5}"
    分类模型给「类别 + 置信度」，adtk 给「是否异常 + 异常分数」。 推理自动出图（预测分布、预测波形），并写 InferenceTasks + 每个样本一行 InferenceResults + 一条 ModelInvocations。
  4. 发布成包，拿给别的机器 需 export:run 权限（删除包需 export:delete） 
    curl.exe -X POST http://127.0.0.1:5000/models/1DCNN/exports -H "Authorization: Bearer <令牌>" -H "Content-Type: application/json" -d "{}"
    产物被打成 zip：权重 + meta.json（输入/输出约定） + README.md + requirements.txt + example_infer.py。 zip 落在 data/exports/<模型名>/，库里 ModelDeployments 记一条流水。
    语义 删除发布包只删磁盘 zip，库记录保留并标成「已删除」 ——包没了，但"曾经发布过 v1"是历史事实，删记录会断审计链。所以删完"发布次数"不会减 1。
  5. 回到页面上看 首页看总览与最近活动；「数据展示」看波形/频谱/图库；「系统管理」看运行环境、11 张表行数、日志与接口索引。 图库里的图可以单张删除（每张图右上角），也可以在「系统管理 → 维护」里一次清空。 每一步都能追到明细。
贯穿全链的设计原则：绝不静默

训练写库失败会降级但显式回报；越界窗口拒绝并计数； 响应里的本机绝对路径统一脱敏；未捕获异常连完整 traceback 一起落盘到 data/logs/error-YYYYMMDD.log。

产物布局的关键约定

data/models/<模型名>/ 下只有一套文件，没有 v1/、v2/ 这种版本子目录。判断一个模型"有没有产物"，看的就是这个目录里有没有权重文件。 早期按版本落盘的布局会被一次性迁移到 data/archive/model_versions/（只归档、不删除）。

08数据库

MySQL 8/9，库名 model_management，字符集 utf8mb4。 共 11 张表（8 张业务表 + 3 张鉴权表）、14 条外键。 只连 MySQL，没有兜底库：MODEL_DB_DIALECT 只接受 mysql， 配成别的值会在启动的 import 期直接报错（避免"看起来能跑"的错觉）。

InferenceTasks推理任务：锚点训练、数据集、参数、输出目录、进度每次 /predict
InferenceResults逐样本结果：窗口标识、预测类别/标签、置信度、异常分数每条推理样本
EdgeDevices边缘设备（预留）：仅一行占位「本地导出」，供发布记录挂外键建表脚本种子
Roles身份：admin 管理员 / user 普通用户（只有两种）首次启动种子 + 旧角色自动收敛
Users用户：用户名(唯一)、PasswordHash(pbkdf2)、角色、IsActive、TokenVersion种子账号 + 用户管理页
OperationLogs操作审计：谁、什么动作、目标、结果、时间各写接口埋点
建表脚本可重复执行，但有一个例外要知道

sql/schema_mysql.sql 用 CREATE TABLE IF NOT EXISTS + INSERT IGNORE， 重跑不会重复插数据。但 EdgeDevices 的种子必须用另一种写法： 该表只有主键、没有业务唯一键（同型号真实设备可以有多台，所以在 DeviceType 上加唯一键是错的）， 于是 INSERT IGNORE 根本不去重——每重跑一次脚本就多插一行同名占位设备。 现在它用的是 INSERT ... SELECT ... WHERE NOT EXISTS，重复执行只在第一次插入。

10登录与会话

登录：走真校验

POST /api/login/ 是匿名可调、不做任何权限控制的——它就是入口， 给入口加权限等于谁都进不来。校验流程是： 查 Users 表 → 用 pbkdf2 比对 PasswordHash → 校验 IsActive → 签发令牌。

失败时不区分"用户不存在"和"密码错误"，统一回同一句话——区分开就等于提供了一个 用户名枚举接口。同理，GET /api/captcha/ 也必须匿名（否则验证码拿不到，人也就登不进来）。

注册：可以自助开号

账号有三个来源

① 自助注册（登录页「注册」页签，见下）； ② 首次启动的种子账号：admin，以及（未配置 MODEL_BOOTSTRAP_ADMIN_PASSWORD 时）演示用的 user（普通用户）； ③ 管理员在「用户管理」页新建（POST /api/system/user/create/，需 user:manage）。

POST /api/register/ 与登录一样是匿名接口、不做权限控制—— 它服务的就是"还没有账号的人"。但"匿名"不等于"随便填"，服务端有几条硬规则：

  • 身份强制为普通用户：请求里带 role/role_key 会被直接忽略。 否则任何人注册时把角色填成 admin 就是一个提权漏洞。要更高权限只能让管理员在「用户管理」页改。
  • 用户名 3~50 字符、不含空格与斜杠；密码 ≥6 位、两次输入一致。
  • 重名会被拒（数据库唯一键）。
  • 账号的 PwdChangeCount 置 1 —— 口令是他自己刚定的，不该再被"初次登录强制改密"拦一次。
  • 若开了验证码（MODEL_CAPTCHA=1），注册同样要过验证码： 否则"登录要人机校验、注册不要"就成了绕过口子，脚本完全可以改用注册接口批量造号。
开关与交付建议

注册由 MODEL_ALLOW_REGISTER 控制，默认打开（内网工具，新人自己开号即可开工）。 关掉（db.env 里写 MODEL_ALLOW_REGISTER=0）后：登录页不显示「注册」页签， 后端接口也直接拒绝。登录页的显隐读的是 /api/init/settings/ 的 base.register_state （与验证码的 captcha_state 同一套机制），所以不会出现"前端显示、后端拒绝"的错配。

交付到工厂等正式环境时建议关掉，改由管理员按需开号 —— 这样账号是可追溯的。

登录页有哪些页签

页签出现条件说明
账号登录总是默认页签，用户名 + 密码（+ 验证码，若开启）
注册base.register_state 为真自助注册，成功后自动登录并进首页
初次登录修改密码该账号 PwdChangeCount=0此时只显示这一个页签（强制改密，不给注册入口）

两种身份

平台只有 admin（管理员） 与 user（普通用户） 两种身份， 差别只有两项：用户管理、查看操作日志。 这两项都涉及别人的账号（能改别人的角色与口令、能看别人干了什么），所以只给管理员。 其余操作两种身份都能做：训练、推理、发布、上传模型与数据集、删除发布包， 以及删除模型产物——它看着危险，但影响面只在本机这一套产物上、重跑训练就能再生， 而各部署点的账号库彼此独立，删本机的模型影响不到任何别人的账号或数据。

管理员在「用户管理」页可以把普通用户设为管理员，也可以停用 / 启用账号 （停用后该账号立即无法登录，记录保留）。两条自锁保护：不能改自己的角色、不能停用自己—— 否则一键就能把最后一个管理员锁在门外。新建账号与自助注册一律默认普通用户， 要管理员权限只能由现有管理员去改。

哪些是按账号隔离的

资源可见范围说明
模型（产物、参数、指标、下载） 共享 平台级资源：任何登录用户都能看、能训练、能发布、能下载 —— 一个实验室/工厂共用一套模型
训练记录（/trainings） 按账号 普通用户只看得到自己发起的训练；管理员看全部
推理流水（/inference-tasks 与逐样本明细） 按账号 同上；而且按 ID 也隔离 —— 拿别人的任务 ID 直接读明细会 404（防越权直读）
数据集 / 发布包 / 图库 / 接口索引 共享 平台级资源（发布包挂在模型上，图是模型产物的一部分）

实现要点：Trainings.CreatedBy / InferenceTasks.CreatedBy 记录真实发起账号 （以前写的是常量 model_service，等于没记），列表与明细查询按它过滤； 发布流水的 DeployedBy 也改成服务端从当前登录用户取，不再信任请求体里传的值。 ⚠️ 三个流水接口因此都要求登录 —— 不要求登录的话，匿名请求没有账号，过滤条件无从谈起。

历史流水的归属不明

改造之前写下的训练/推理记录，CreatedBy 是常量 model_service， 所以普通用户看不到它们（管理员仍能看到全部）。记录本身没丢。

已登录之后：个人资料与修改密码在哪

在右上角头像的下拉菜单里：

菜单项打到的接口行为
个人资料POST /api/system/user/update_user_info/ 改显示名 / 邮箱 / 手机。⚠️ 明确不改角色：请求体里的 role 字段会被服务端丢弃（否则任何登录用户都能把自己改成 admin）。
修改密码POST /api/system/user/change_password/ 填原密码 + 新密码两遍。改完 TokenVersion +1、旧令牌立即失效， 后端会下发新令牌，前端自动换上 —— 所以不用重新登录，其它设备上的会话则会被踢下线。

「改密码」一共有三条路，别混淆：① 上面这个自助修改； ② 初次登录强制改密（登录页的独立页签，PwdChangeCount=0 时才出现）； ③ 管理员在「用户管理」页重置他人密码（需 user:manage，同样会让对方当前会话失效）。

令牌怎么带

三种写法后端都认，按优先级：

方式写法什么时候用
标准头（推荐）Authorization: Bearer <令牌>前端 platformRequest 用的就是这个
自定义头token: <令牌>兼容模板旧写法
查询参数?token=<令牌>仅用于浏览器直接下载（<a href> 带不了自定义头）

令牌有效期默认 12 小时（MODEL_TOKEN_TTL_HOURS）。 服务端每次请求都会回库核对用户现状：管理员停用某人、改其角色、 或重置/修改其口令（会把 TokenVersion +1），该用户手上的旧令牌立即失效， 不会因为"还没过期"而继续可用。

没配 MODEL_SECRET_KEY 会怎样

服务每次启动都会随机生成一个签名密钥 → 每重启一次（开发模式下改任何 .py 都会自动重载） 所有人被登出。日志里表现为"令牌校验未通过"。配好密钥即可，重启不掉线。

交付前必做

① 删掉或改掉演示账号的口令（user / User@2026 是公开的演示口令）； ② 把 db.env 里的 MODEL_SECRET_KEY 换成随机值； ③ 确认 MODEL_AUTH_DISABLED 没有被打开（打开时 /health 会显式回报 auth_disabled）； ④ 决定要不要留自助注册：正式交付建议 MODEL_ALLOW_REGISTER=0； ⑤ 建议开 MODEL_CAPTCHA=1（登录接口没有失败计数，弱口令能被在线慢爆破）； ⑥ 把上面四项一起看一遍：匿名 GET /health 的 config.auth 块会把 enabled / key_is_default / allow_register / captcha_enabled 全列出来，不用去翻代码。

12常见问题与排查

下面这些都是开发过程中真实踩过、并且已经在代码里留了说明的坑。

前端 / 联调

页面能打开，但所有数据都是空的，控制台报「非标准返回」

平台接口走了 dvadmin 框架的信封校验。修法是让页面用 utils/platformRequest.ts 这个不走信封校验的 axios 实例。 自己新增接口调用时请沿用该实例（src/api/platform/index.ts 里都是这么写的）。

跨域被拦：CORS policy: preflight ... does not have HTTP ok status

兼容层已统一放行所有 OPTIONS 预检，所以这个报错通常不是 CORS 配置问题， 而是"那个接口根本没注册"——预检命中 404 被浏览器包装成了跨域错误。 先在网络面板看该请求的真实状态码。 若确实刚改过后端路由，请确认后端重启过（改路由注册必须重启，debug 自动重载不重注册蓝图）。

改了后端代码没生效

/train 与产物注册相关的改动必须重启后端；其余改动在 debug 模式下会自动重载。

上传数据集后，列表里看不到新文件

上传后会主动清体检缓存；若用的是旧版本，刷新页面或等 120 秒 TTL 过期。

训练 / 推理

训练报「数据集目录不存在」

dataset_dir 要用工作区相对路径，例如 1DCNN/0HP。 后端按「工作区 → 项目目录」顺序解析，绝对路径也接受但必须在工作区内。

训练成功，但模型没能存下来（Keras 报临时目录写入失败）

Keras 的 model.save() 会先写一个临时文件再改名。在某些受限环境（严格 ACL、沙箱）下 这一步会抛 PermissionError。代码里 config.ensure_writable_tempdir() 会先探测 系统临时目录是否可写，不可写就整体退回到项目内的 data/tmp； 同时权重保存会回退到 h5py 直写的 .h5，并把失败的 .keras 半成品删掉。

准确率看着不错，但某一类好像从没被测过

看产物 metrics.untested_labels。当前 1DCNN 产物里是 「内圈故障-0.014in」——原因见 §04 的 IR014 说明。

多人同时点训练，后端像卡住了

本项目不做训练排队，/train 是同步阻塞的，会一直占着工作线程直到训练结束。 开发用 Flask 自带服务器；生产用 serve.py（waitress 多线程，默认 4 线程）。

登录与账号

登录页看不到「注册」页签

两种情况：① 后端把注册关掉了（MODEL_ALLOW_REGISTER=0，或 db.env 里没生效） —— 可以打开 /api/init/settings/ 看 base.register_state 是不是 false； ② 你所在的账号处于"初次登录强制改密"状态（PwdChangeCount=0），此时只显示改密页签。 另外注册页签的显隐依赖一次系统配置请求，页面刚打开的一瞬间可能还没到。

注册时提示"该角色不合法"或角色不是我要的

注册只能拿到普通用户，这是服务端写死的（防止注册即提权）。 需要训练/发布/用户管理权限，请让管理员在「用户管理」页改你的角色。

改了密码之后，其它设备上的登录被踢了

这是预期行为：改密会把 TokenVersion +1，所有旧令牌立即失效。 当前这台设备会自动换上后端下发的新令牌，所以自己不受影响。

登录后没多久就掉线，或者每次重启都要重新登录

没配 MODEL_SECRET_KEY。此时服务每次启动随机生成密钥，旧令牌全部失效。 在 db.env 里配一个固定随机值即可。

点了某个按钮提示"没有权限"

当前账号的角色不够。前端隐藏按钮只是体验，真正的拦截在后端： 业务接口返回 403 并带上需要的权限点，兼容层回 code=4000 + 文案。 需要更高权限时，联系管理员在「用户管理」页调整你的角色。

下载发布包报 401

GET /models/<模型>/exports/<包> 需要登录（任何角色都能下载，但要有身份）。 浏览器直接点下载时带不了自定义头，所以前端用 fileUrl() 自动附加 ?token=。

13已知限制

以下都是当前真实存在的边界。写在这里是为了避免误读指标，也避免重复踩坑。

数据

IR014 类别不参与指标

该文件只有 63,788 点，默认参数下 180 个测试窗全部越界被跳过。看准确率时务必同时看产物里的 untested_labels。

模型

cwt_cnn 精度明显偏低

同任务的 PyTorch 实现测试准确率 0.6680，远低于 1DCNN 的 0.9457。这是实现差异，不是数据问题。

并发

不排队，训练同步阻塞

没有任务队列。/train 会占住一个工作线程直到训练结束，多人同时训练会明显变慢。

鉴权

两个匿名可写的接口已补上登录检查 ✅

原先 POST /system/maintenance（清空图库）与 POST /api/system/file/ （上传文件到 data/uploads/）对匿名请求开放，没有任何登录检查。 现已各补一道登录校验，并且维护操作会写一条 maintenance 操作日志（能追到是谁按的）。

顺带说清剩下的边界：只读的业务接口仍是匿名可读的（内网共享的定位， 见 §09 的「认证」列），但所有会改数据的接口都要求登录。

隔离

历史流水没有归属账号，普通用户看不到 ⚠️

Trainings.CreatedBy / InferenceTasks.CreatedBy 这两个字段以前 写的是常量 model_service（不是真实账号），现在已改成写真实账号。 代价是：改造之前产生的历史流水归属不明， 按账号隔离后普通用户看不到它们（管理员仍能看到全部）。 这些历史记录本身没丢，用管理员账号进「训练记录 / 推理任务」即可查到。

鉴权

自助注册默认是开着的

任何人打开登录页都能自己注册一个普通用户账号（身份被服务端锁死，提不了权）。 内网工具这样最省事，但交付到工厂等正式环境前建议在 db.env 里写 MODEL_ALLOW_REGISTER=0 关掉，改由管理员按需开号，账号才可追溯。

依赖

依赖清单与真实环境有偏差

requirements.txt 钉的是正式版 TensorFlow / Keras，而开发机 venv 实装的是 nightly 版本。 在新机器上照清单安装后能否加载现有 .keras 产物尚未验证。

指标

部分历史数值不可复现

项目文档里个别早期手工测算的数值（如某些 AUC / 误报率）没有入库、也没有复现脚本。 本页只引用产物 meta.json 与 detector.pkl 里可核验的字段。

部署

内网定位，非公网服务

按"实验室内网"设计。若要暴露到更大网络，请自行加 HTTPS、改默认口令、限制 /media/ 与匿名接口的访问，并确认 MODEL_AUTH_DISABLED 没被打开。

前端

未内置前端构建产物

仓库里没有 dist/（也不该提交）。单端口部署前必须先跑 npm run build:singleport，否则后端只会给一个"前端未构建"的提示页。

更细的内容见仓库内 README.md、项目交接文档.md、项目技术详解.md， 以及 docs/ 下的 Windows / Linux 部署手册。 本页是可离线打开的单文件，可直接拷贝分发。
