# 实验室机器升级指南（单端口 + 鉴权版）

> **适用场景**：实验室那台离线电脑上**已经跑着旧版**（要开两个窗口、5000 + 8080、
> 登录随便填），现在要升级成新版：**单端口 8080、有真实登录、开机自启**。
>
> 如果你还没装过，请看 `离线部署手册.md`，走完整安装流程。

---

## 这次升级改了什么（先看一眼，知道为什么要做这些步骤）

| | 旧版 | 新版 |
|---|---|---|
| 启动方式 | 开两个黑窗口（后端 5000 + 前端 8080） | **一个服务，开机自动跑** |
| 访问地址 | 两个端口，容易输错 | **只输 `http://<IP>:8080`** |
| 登录 | 随便填都能进，且都是超管 | **真实校验**，三种角色权限不同 |
| 关掉窗口 | 服务就停了 | 服务在后台，关窗口不影响 |
| 崩溃 | 就挂了，要人手动重启 | **15 秒后自动拉起** |

⚠️ **升级前后最大的坑**：数据库结构变了。
旧库只有 8 张表，新版多了 `Users` / `Roles` / `OperationLogs` 三张。
**不补这三张表，更新完代码一登录就报错**（`Table 'model_management.Users' doesn't exist`）。

---

## 升级步骤（照着做，约 15 分钟）

### 第 0 步：先备份（2 分钟，别跳过）

在实验室电脑上，管理员 PowerShell 里执行：

```powershell
# 建个备份目录
mkdir D:\backup-$(Get-Date -Format yyyyMMdd) -Force

# 备份数据库（会提示输 MySQL root 密码）
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe" `
    -u root -p model_management `
    > "D:\backup-$(Get-Date -Format yyyyMMdd)\model_management.sql"
```

> ⚠️ 如果 MySQL 是解压版（不是安装版），`mysqldump.exe` 在解压目录的 `bin\` 下，
> 把上面的路径换成实际路径。

**为什么必须备份**：升级要在旧库上执行建表语句。万一中途出错（比如编码不对），
有备份就能整体回滚；没有备份就只能重建整个库，训练记录和模型登记全丢。

顺便把代码目录也复制一份：

```powershell
Copy-Item D:\项目目录\testRestfulProject D:\backup-$(Get-Date -Format yyyyMMdd)\testRestfulProject -Recurse
```

---

### 第 1 步：拿到新版代码

在你**自己的笔记本**上（联网那台）先把代码推到 GitHub：

```powershell
cd D:\HUAT\22project
git add -A
git commit -m "升级：单端口部署 + 真实鉴权 + 服务化"
git push origin main
```

然后在笔记本上打一个**代码更新包**：

```powershell
cd D:\HUAT\22project
powershell -ExecutionPolicy Bypass -File tools\make-update-package.ps1
```

它会生成 `code-update-<日期>\` 目录和同名 zip。**把它拷到优盘。**

> ⚠️ 更新包**不含** `data\models\`（训练好的模型产物）和 `node_modules`，
> 所以通常只有几百 KB 到几 MB。模型产物如果也要同步，见文末「附：同步模型产物」。

---

### 第 2 步：在实验室电脑上应用代码

1. 优盘插到实验室电脑上，把 `code-update-<日期>\` 整个拷到任意位置（比如桌面）。
2. **先停掉正在跑的服务**：
   - 如果还是旧版（两个黑窗口）→ 直接关掉那两个窗口。
   - 如果已经装了服务 → 管理员 PowerShell：`net stop ModelPlatform`
3. 管理员 PowerShell 里执行：

```powershell
cd <你拷贝到的位置>\code-update-<日期>
powershell -ExecutionPolicy Bypass -File .\应用更新.ps1
```

脚本会自动备份被覆盖的文件（放到项目目录同级的 `_backup-<时间戳>\`）。

> ⚠️ 更新包里的脚本名是 **`应用更新.ps1`**（打包时自动改的中文名，对用户友好）；
> 项目 `tools\` 里的源文件名是 `apply-update.ps1`，是同一样东西。

> ⚠️ `应用更新.ps1` **不会**覆盖 `db.env` 和 `venv\`
> —— 这两样是每台机器各自的，覆盖了就会把数据库连接信息和虚拟环境弄坏。
>
> ✅ 但它**会**覆盖 `frontend\22project\dist`（前端构建产物），
> 这正是本次前端修复能生效的关键。

---

### 第 3 步：补数据库表（这次升级的关键一步）

在实验室电脑上执行：

```powershell
cd <项目目录>\testRestfulProject
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p < sql\auth-migration.sql
```

**验证是否成功**（应该返回 3 行）：

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p -e `
  "SELECT TABLE_NAME FROM information_schema.TABLES WHERE TABLE_SCHEMA='model_management' AND TABLE_NAME IN ('Users','Roles','OperationLogs');"
```

看到 `Users` / `Roles` / `OperationLogs` 三行就对了。

> **这个脚本是幂等的**：重复跑不会报错、不会重复插数据。
> 所以就算你不确定跑没跑过，直接再跑一遍是最省事的做法。
>
> ⚠️ 它**只建表、只插角色，不建任何账号**。账号由服务启动时自动创建（下一步）。

---

### 第 4 步：配置令牌密钥（重要，别跳过）

在实验室电脑上编辑 `<项目目录>\testRestfulProject\db.env`，
**在文件末尾加上**：

```ini
MODEL_SECRET_KEY=<换成你自己的随机字符串>
MODEL_TOKEN_TTL_HOURS=12
MODEL_BOOTSTRAP_ADMIN_PASSWORD=
```

**怎么生成随机字符串**：随便敲一串 32 位以上的无规律字符就行，比如
`k7Xm2Qw9Zp4Ln8Rt6Vy3Bc5Hj1Sd0FgA`。也可以在这台机器上跑：

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

> ⚠️ **为什么不配不行**：不配的话，服务每次重启都会用一个**新的随机密钥**，
> 于是所有已登录的人立刻掉线。演示时重启一次服务、大家全被踢回登录页，
> 会被当成"系统不稳定"。配了固定密钥就没这个问题。
>
> ⚠️ **以后换掉这个值 = 所有人立即掉线**（等价于强制全体重新登录）。
> 平时不要动它。

`MODEL_BOOTSTRAP_ADMIN_PASSWORD` 留空即可 —— 留空会建三个演示账号（见下一步）。

---

### 第 5 步：确认前端产物（更新包已自带，通常无需操作）

⚠️ **前端必须与后端同源**才能用单端口访问。旧版的产物指向 `http://127.0.0.1:5000`，
新版要改成同源（走当前端口）。产物不对的话，打开页面会一片空白、接口全 404。

**好消息：更新包已经自带构建好的 `dist`，正常情况下你不用做任何事。**

`make-update-package.ps1` 会把笔记本上 `frontend/22project/dist` 一起打进包里，
`应用更新.ps1` 覆盖时会把它同步到实验室机器的
`<项目目录>\frontend\22project\dist` —— 这正是后端会自动探测的第一个位置。

> ⚠️ **不要**把 `dist` 放到 `testRestfulProject\data\web`。
> 后端确实也探测那个位置（见 `web.py` 的 `_dist_dir()`），但：
> - `应用更新.ps1` **只覆盖 `frontend\22project\dist`**，不会碰 `data\web`
> - 结果就是：你以为更新了，其实后端读的还是 `data\web` 里的旧产物
> - 表现为「改了前端、页面没变」，而且很难排查
>
> 所以**统一放在 `frontend\22project\dist`**，别用 `data\web`。

**先确认产物里含本次修复**（可选，但推荐）：

```powershell
Select-String -Path "<项目目录>\frontend\22project\dist\assets\*.js" -Pattern "Bearer " -List |
  Select-Object -First 3 -ExpandProperty Filename
# 期望：列出至少一个文件名。一条都没有 → 产物是旧的，走下面的做法 A
```

**只有在下面两种情况才需要重新构建**：
- 更新包里**没有** `dist`（打包时笔记本上还没 build，打包脚本会黄字警告）
- 你确认前端有改动，但产物是旧的

**做法 A（在实验室电脑上构建，需要它装过 Node.js）**

```powershell
cd <项目目录>\frontend\22project
npm run build:singleport
```

> 用 `build:singleport`（等价于 `npm run build -- --mode singleport`），
> 它会读 `.env.singleport`，保证 `VITE_API_URL` 是对的。

**做法 B（在笔记本上构建好，把 `dist` 整个拷过去）**

```powershell
# 笔记本上
cd D:\HUAT\22project\frontend\22project
npm run build:singleport
# 然后把 dist 目录整个拷到优盘
```

到实验室电脑上，把 `dist` 覆盖到 **`<项目目录>\frontend\22project\dist`**
（删掉旧的再放，别只往里叠加，否则旧的带 hash 的 js 会残留）。

### 第 6 步：装成服务（从此不用管）

**先确认装了 `nssm`**：把 `nssm.exe` 放到部署脚本目录的 `nssm\` 子目录下。
没有的话去 https://nssm.cc/download 下载（免安装，解压出来就是单个 exe）。

然后管理员 PowerShell：

```powershell
cd <部署脚本目录>
.\05-install-service.ps1
```

或者用统一入口（会自动请求提权）：

```powershell
.\run.bat 05
```

脚本会：注册服务 → 设置开机自启 → 配置崩溃自动重启 → 放行防火墙 8080 → 启动并探测。

**装完后验证**：

```powershell
Get-Service ModelPlatform          # 状态应该是 Running
Invoke-WebRequest http://127.0.0.1:8080/health -UseBasicParsing | Select-Object -Expand StatusCode
```

浏览器打开 `http://localhost:8080`，应该看到登录页。

### 第 7 步：登录并改密码

用种子账号登录：

| 账号 | 口令 | 用途 |
|---|---|---|
| `admin` | `Admin@2026` | 给老师的主账号，全部权限 |
| `engineer` | `Engineer@2026` | 演示"能训练、不能管用户" |
| `operator` | `Operator@2026` | 演示"只能看和推理，不能训练/发布/删除" |

⚠️ **这三个是公开的演示口令，正式使用前必须改掉**：
登录后进「系统管理 → 个人中心 → 修改密码」。
改完密码**当前令牌立即失效，需要重新登录**（这是有意设计，防止旧令牌继续可用）。

不需要的演示账号，交付时可以停用（数据库 `Users` 表里把 `IsActive` 改成 0）。

## 附：验证升级成功（5 项自查）

在新版机器上逐条确认：

```powershell
# ① 服务在跑
Get-Service ModelPlatform

# ② 首页能开（返回 HTML）
(Invoke-WebRequest http://127.0.0.1:8080/ -UseBasicParsing).StatusCode    # 期望 200

# ③ 接口还在（返回 JSON）
(Invoke-WebRequest http://127.0.0.1:8080/health -UseBasicParsing).StatusCode  # 期望 200

# ④ 前端路由刷新不白屏（这是 SPA 兜底，最容易漏）
(Invoke-WebRequest http://127.0.0.1:8080/platform/model -UseBasicParsing).StatusCode  # 期望 200

# ⑤ 未登录调受保护接口必须被拒
try { Invoke-WebRequest http://127.0.0.1:8080/train -Method POST -Body '{}' -ContentType 'application/json' -UseBasicParsing }
catch { $_.Exception.Response.StatusCode.value__ }   # 期望 401
```

再加一条**肉眼检查**：在「模型管理」页面按一下 **F5**。
页面应该正常重载，**不是白屏**。这一条最能说明单端口托管配对了。

## 出问题了怎么查

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 浏览器打开是"后端已启动，但还没有前端页面" | 前端产物没到位（`dist` 缺失或位置不对） | 回到第 5 步 |
| 页面一片空白，F12 里一堆 404 | 前端产物是旧模式构建的（指向 5000），或产物没覆盖成功 | 回到第 5 步，确认用的 location 是 `frontend\22project\dist` |
| 登录成功却提示"登录已失效"（4000） | 浏览器缓存了旧的 JS（旧代码发 `JWT` 前缀，后端只认 `Bearer`） | **`Ctrl + F5` 强制刷新**；仍不行就用无痕窗口 |
| 登录报 `Table ... doesn't exist` | 没跑迁移 SQL | 回到第 3 步 |
| 重启服务后所有人都被踢下线 | `MODEL_SECRET_KEY` 没配 | 回到第 4 步 |
| 服务起不来 | 数据库连不上，或端口被占 | 看 `testRestfulProject\data\logs\service-err.log` |
| 局域网别的电脑连不上 | 防火墙没放行 8080 | `New-NetFirewallRule -DisplayName '模型管理平台' -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow` |
| 改了后台代码，前台没变化 | 前端产物是静态的，不会自动更新 | 确认更新包含 `dist` 且覆盖到了 `frontend\22project\dist`；必要时 `npm run build:singleport` |
| 前端改了但页面没变 | 产物没更新，或浏览器缓存 | 确认 `dist` 已覆盖 → `Ctrl + F5` |

**日志在哪**：

| 日志 | 位置 | 什么时候看 |
|---|---|---|
| 服务输出 | `testRestfulProject\data\logs\service-out.log` | 想知道服务有没有正常启动 |
| 服务错误 | `testRestfulProject\data\logs\service-err.log` | **服务起不来时第一个看这里** |
| 未捕获异常 | `testRestfulProject\data\logs\error-<日期>.log` | 接口报 500 时看这里（有完整 traceback） |

## 一分钟速查（熟练之后只看这段）

```powershell
# 笔记本：推代码 + 打包
cd D:\HUAT\22project; git add -A; git commit -m "update"; git push
powershell -File tools\make-update-package.ps1

# 实验室机器（管理员 PowerShell）
net stop ModelPlatform
cd <更新包目录>; powershell -File 应用更新.ps1
cd <项目>\testRestfulProject
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p < sql\auth-migration.sql

# 启动
net start ModelPlatform
# 浏览器 http://localhost:8080 然后 Ctrl + F5
```

> **前端不用重新 build** —— 更新包已自带 `dist`（含本次 Bearer 修复）。
> 只有打包时笔记本上还没 build（脚本会黄字警告）才需要手动构建，
> 且产物必须放在 `frontend\22project\dist`（**不是** `data\web`）。
