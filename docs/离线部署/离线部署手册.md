## 0. 先看这里：整体流程

整个事情分两个阶段，**别搞反了**：

```
【阶段一】在有网的电脑上（你现在这台）
   下载安装程序 → 下载 Python 依赖 wheel → 拷贝前端 node_modules
   → 拷项目源码 → 全部塞进优盘
                    │
                    │  优盘
                    ▼
【阶段二】在实验室离线电脑上
   装 Python / Node.js / MySQL → 拷项目 → 建 venv 装依赖
   → 建数据库 → 启动系统 → 打开网页
```

**关键认知（很重要，先看一眼）**：

| 东西 | 能不能直接拷 U 盘搬过去？ | 原因 |
|---|---|---|
| 项目源码（`.py` / `.vue` / 模型文件） | ✅ 能 | 纯文本和权重，与机器无关 |
| Python 依赖 wheel 包 | ✅ 能 | 但要用 `pip install` 装，不能拷 `venv` 文件夹 |
| 前端 `node_modules` | ✅ 能 | 同平台（都是 Windows x64）可直接用 |
| **`venv` 文件夹** | ❌ **不能** | 里面写死了本机路径，换台机器直接坏 |
| MySQL 数据目录 | ⚠️ 建议不搬 | 用建表脚本重建更干净 |

关于最后两条为什么不建议，见 [附录 A](#附录-a为什么不能直接复制-venv)。

## 1. 准备工作（在能上网的电脑上完成）

> 如果你拿到的是**已经打包好的优盘**，这一节可以跳过，直接看第 3 节。

### 1.1 需要下载的三个安装程序

放到优盘的 `01-安装程序\` 目录里。**版本尽量与下表一致**，否则 Python 依赖的 wheel 可能对不上。

| 软件 | 推荐版本 | 下载地址 | 安装包大概大小 |
|---|---|---|---|
| **Python** | 3.12.4（Windows installer 64-bit） | https://www.python.org/downloads/release/python-3124/ | ~25 MB |
| **Node.js** | 18.20.4 LTS（`.msi` 64-bit） | https://nodejs.org/dist/v18.20.4/ | ~28 MB |
| **MySQL** | 8.0.34 免安装 ZIP 版 | https://dev.mysql.com/downloads/mysql/8.0.html | ~200 MB |

**下载时的注意事项**：

- **Python**：选 `Windows installer (64-bit)`。安装时**一定要勾选 `Add python.exe to PATH`**，否则后面脚本找不到 `python` 命令。
- **Node.js**：选 `node-v18.20.4-x64.msi`。
- **MySQL**：推荐下 **ZIP Archive 免安装版**（不是 MSI）。免安装版的好处是：整个文件夹拷到哪都能跑，不写注册表，特别适合离线电脑。下 `mysql-8.0.34-winx64.zip`。

> 💡 如果懒得下 MySQL，也可以从当前这台电脑的 `D:\HUAT\mysql-8.0.34-winx64\` 整个文件夹拷进优盘（你本机用的就是这个免安装版）。

### 1.2 Python 依赖 wheel 包

已打包在 `02-Python离线依赖\`，共 **86 个 .whl 文件、约 630 MB**（含 TensorFlow 351 MB + PyTorch 118 MB）。

如果需要重新生成，在有网的电脑上执行：

```powershell
cd D:\HUAT\22project\testRestfulProject

# 1) 先下 torch 的 CPU 版（注意：必须从 PyTorch 官方索引，PyPI 上没有 +cpu 后缀）
venv\Scripts\python.exe -m pip download "torch==2.14.0+cpu" `
    -d "D:\HUAT\22project\offline_package\02-Python离线依赖" `
    --index-url https://download.pytorch.org/whl/cpu --only-binary=:all:

# 2) 再下其余全部依赖
venv\Scripts\python.exe -m pip download `
    -r "D:\HUAT\22project\offline_package\02-Python离线依赖\requirements-offline.txt" `
    -d "D:\HUAT\22project\offline_package\02-Python离线依赖" --only-binary=:all:
```

> ⚠️ **注意**：这里用的是 `requirements-offline.txt`，**不是**项目里的 `requirements.txt`。
> 原因：离线清单是从本机真实环境（`pip freeze`）倒推的，**多退少补都经过实测**，
> 且剔除了不该走 pip 的包（如源码内置的 `adtk`）。用离线清单可以一步到位。
> 项目里的 `requirements.txt` 已在本次打包时修正（原本漏了 `tensorflow` 等），
> 现在两者内容基本一致，见 [附录 B](#附录-b给维护者的话)。

### 1.3 前端依赖

`node_modules` 已直接拷进 `03-前端离线依赖\node_modules\`（约 641 MB / 45,304 个文件）。

**为什么前端可以直接拷 `node_modules`，Python 却不行？**

因为 `node_modules` 里装的是**纯 JS 代码**，不含解释器本体，路径也是相对引用的；
而 Python 的 `venv` 里 `python.exe` 只是个 264 KB 的**跳板**，真正指向的是本机安装的 Python 解释器 —— 换台电脑那个路径就不存在了。

### 1.4 数据库

`05-数据库\01-建库建表.sql` 已经是从 `testRestfulProject/sql/schema_mysql.sql` 复制过来的建表脚本，
自带 `CREATE DATABASE` + `USE` + 8 张表的 `CREATE TABLE IF NOT EXISTS`，可以重复执行。

> ⚠️ 注意：项目 `sql\` 目录里还有个 `schema.sql`，那是 **SQL Server (T-SQL) 版**的旧脚本，
> **不要在 MySQL 上用**。MySQL 认准 `schema_mysql.sql`。

## 3. 实验室电脑的部署步骤

> **全程按这个顺序做，别跳步。** 共 4 步，每步对应 `06-部署脚本\` 里的一个 `.ps1`。
>
> **怎么运行这些脚本**（三种方式任选）：
> 1. 在 `06-部署脚本\` 文件夹里，地址栏输入 `cmd` 回车，然后敲 `run.bat 01`（把 01 换成对应步骤号）
> 2. 右键对应的 `.ps1` 文件 →「使用 PowerShell 运行」
> 3. 命令行：`powershell -ExecutionPolicy Bypass -File "脚本完整路径"`
>
> > 如果提示「无法加载文件，因为在此系统上禁止运行脚本」，用第 1 种或第 3 种方式（第 3 种带了 `-ExecutionPolicy Bypass`）。

### 第 0 步：装三个基础软件

按 `01-安装程序\` 里的包，依次安装。**顺序无所谓，但都装完再往下走。**

#### (1) 装 Python

双击 `python-3.12.4-amd64.exe`：

- ✅ **勾选 `Add python.exe to PATH`**（在最下面一排，**千万别漏**）
- 选 `Install Now` 即可

装完验证：打开「命令提示符」（Win+R 输入 `cmd`），敲：

```cmd
python --version
```

应显示 `Python 3.12.4`。如果提示「不是内部或外部命令」，说明 PATH 没勾上，重新装一遍或手动加环境变量。

#### (2) 装 Node.js

双击 `node-v18.20.4-x64.msi`，一路默认下一步即可。

装完验证：

```cmd
node -v
npm -v
```

应显示 `v18.20.4` 和 `10.7.0` 左右。

#### (3) 装 MySQL

**如果用 ZIP 免安装版**（推荐）：

1. 把 `mysql-8.0.34-winx64.zip` 解压到某个不带中文和空格的路径，例如 `D:\mysql-8.0.34`
2. 在该目录下**新建一个 `my.ini`**，内容如下（**路径按你的实际位置改**）：

```ini
[mysqld]
basedir=D:/mysql-8.0.34
datadir=D:/mysql-8.0.34/data
port=3306
character-set-server=utf8mb4
collation-server=utf8mb4_unicode_ci

[client]
default-character-set=utf8mb4
```

3. 以**管理员身份**打开命令提示符，初始化数据目录：

```cmd
cd /d D:\mysql-8.0.34\bin
mysqld --initialize-insecure --console
```

> `--initialize-insecure` 表示 root 账号**不设密码**。为了跟项目里 `db.env` 的默认密码 `1006` 对上，装完请改一下密码（见下一步）。

4. 注册成 Windows 服务并启动：

```cmd
mysqld --install MySQL --defaults-file="D:\mysql-8.0.34\my.ini"
net start MySQL
```

5. 给 root 设置密码（与项目默认配置保持一致）：

```cmd
mysql -u root
```

进入 MySQL 后执行：

```sql
ALTER USER 'root'@'localhost' IDENTIFIED BY '1006';
FLUSH PRIVILEGES;
EXIT;
```

> 💡 **如果你想用别的密码**：没问题，但一定要同步改
> `04-项目源码\testRestfulProject\db.env` 里的 `MODEL_DB_PASSWORD`，否则后端连不上库。

**如果用的是 MSI 安装版**：安装向导里会让你设 root 密码。把设好的密码记下来，
同样要同步到 `db.env`。另外 MySQL 8 默认会开 SSL，本项目的连接脚本已处理，不用额外配置。

### 第 1 步：安装后端依赖

运行 `06-部署脚本\run.bat 01`（或右键 `01-install-backend.ps1` →「使用 PowerShell 运行」）。

脚本会做这些事：

1. 检查有没有 `python` 命令，并确认是 3.12.x
2. 在 `04-项目源码\testRestfulProject\` 下创建 `venv` 虚拟环境
3. 用 `pip install --no-index --find-links=...` 从本地 wheel 装全部依赖
4. 验证 flask / tensorflow / torch 能否正常导入

**这一步最慢，约 5~10 分钟**（2.6 GB 的包装到磁盘上）。中途不要关窗口。

成功的话最后会看到：

```
   [OK]   Flask / PyMySQL / numpy / pandas / matplotlib / sklearn / statsmodels / tabulate
   [OK]   torch
         torch 2.14.0+cpu
   [OK]   tensorflow
         tensorflow 2.21.0
```

> ⚠️ **报错「Python 版本不对」怎么办**：本包的 wheel 都是给 **cp312**（Python 3.12）准备的。
> 如果你装的是 Python 3.11 或 3.13，要重新在能上网的电脑上按你的版本下 wheel。

### 第 2 步：初始化数据库

运行 `06-部署脚本\run.bat 02`。

脚本会问你 MySQL 的账号和密码（直接回车就用 `db.env` 里已有的值，默认 `root` / `1006`），
然后执行建库建表脚本，最后校验 8 张表。

成功的话会看到：

```
   [OK]   8 张表全部就位
```

> 💡 如果这步失败，也可以手动来：打开 Navicat / MySQL Workbench，
> 把 `05-数据库\01-建库建表.sql` 拖进去执行一遍，效果完全一样。

---

### 第 3 步：检查配置

运行 `06-部署脚本\run.bat 03`。

这是一步**自检**，会在正式启动前把常见的坑一次性排掉。它会检查：

- `db.env` 里的数据库配置对不对（是不是 mysql、账号密码填了吗）
- venv 和关键依赖装好了吗（含 tensorflow / torch 能否导入）
- 三个模型的产物在不在
- 前端 `node_modules` 拷过去了吗
- `.env.development` 里有没有 `VITE_PORT = 8080`
- Node.js 装好了吗
- MySQL 服务在运行吗
- 5000 / 8080 端口有没有被占用

全通过的话会显示「**自检通过**」。如果有问题，它会明确告诉你哪一项不对、怎么修。

---

### 第 3.5 步：拷贝前端依赖 + 构建前端产物

**这一步很容易漏，但很关键。** 分两小步。

#### 3.5A：拷贝 `node_modules`

把优盘里的 `03-前端离线依赖\node_modules\` **整个文件夹**，
复制到实验室电脑的：

```
04-项目源码\frontend\22project\node_modules
```

> 💡 45,304 个文件，用文件资源管理器复制会有点慢。想快一点可以开命令行用 `robocopy`：
>
> ```cmd
> robocopy "优盘盘符:\模型管理平台-离线部署包\03-前端离线依赖\node_modules" ^
>          "D:\模型管理平台-离线部署包\04-项目源码\frontend\22project\node_modules" ^
>          /E /MT:16
> ```

#### 3.5B：构建前端产物（单端口模式必须做）

```powershell
cd D:\模型管理平台-离线部署包\04-项目源码\frontend\22project
npm run build -- --mode singleport
```

跑完会在 `frontend\22project\dist\` 下生成 `index.html` 和 `assets\`。

> ⚠️ **为什么必须是 `--mode singleport`**：这个模式让前端请求打到
> "当前页面的地址"而不是写死的 `http://127.0.0.1:5000`。
> 用默认模式构建的话，你在**别的电脑**上打开页面，浏览器会去连那台电脑自己的 5000 端口
> ——必然连不上，表现为白屏加一堆失败请求。
>
> ⚠️ **前端代码改了就要重新构建一次**（改后端 Python 不用）。
> 构建产物是静态文件，不会自动跟着源码变。

**如果这台机器没装 Node.js、也不想装**：可以在你自己电脑上构建好，
把 `dist` 整个目录拷到优盘，然后放到实验室电脑的

- `04-项目源码\frontend\22project\dist`，或
- `04-项目源码\testRestfulProject\data\web`

两个位置**放哪个都行**，后端会自动去找（先找第一个）。

### 第 4 步：启动系统

> ⚠️ **有两种启动方式，请先看清楚再选**：
>
> | | `run.bat 04`（开发模式） | `run.bat 05`（生产模式）**← 推荐** |
> |---|---|---|
> | 端口 | 两个：后端 5000 + 前端 8080 | **一个：8080** |
> | 窗口 | 开两个黑窗口，**关了服务就停** | 后台服务，**开机自启、崩溃自动重启** |
> | 用途 | 改代码调试时用 | **交付/演示用这个** |
>
> 下面先讲生产模式（交付用），再讲开发模式（调试用）。

#### 4A. 生产模式（交付用，推荐）

先确认**前端已经构建过**（见第 3 步末尾的说明），然后运行
`06-部署脚本\run.bat 05`（会自动申请管理员权限）。

脚本会依次完成：注册 Windows 服务 → 设置开机自启 → 配置崩溃自动重启
→ 放行防火墙 8080 → 启动服务并探测 `/health`。

装完之后，**不用再手动启动任何东西**。开机就是跑着的状态。

浏览器（建议 Chrome / Edge）访问：

**http://localhost:8080**

登录用：

| 账号 | 口令 |
|---|---|
| `admin` | `Admin@2026` |
| `engineer` | `Engineer@2026` |
| `operator` | `Operator@2026` |

> ⚠️ 这三个是**公开的演示口令**，正式使用前请登录后修改密码。
> 演示时可以分别用三个账号登录，直观看出"不同角色能做的事不一样"：
> `operator` 看不到「开始训练」和「发布」按钮，`engineer` 能训练但不能管用户。

局域网里别的电脑访问，把 `localhost` 换成这台机器的 IP（脚本结束时会打印出来）。

**常用服务命令**（管理员 PowerShell）：

```powershell
net start ModelPlatform          # 启动
net stop  ModelPlatform          # 停止
Restart-Service ModelPlatform    # 重启
Get-Service ModelPlatform        # 看状态
```

**卸载服务**：`06-部署脚本\run.bat 06`（只删服务注册，数据库和模型产物都保留）。

#### 4B. 开发模式（改代码调试时用）

运行 `06-部署脚本\run.bat 04`。

会弹出**两个 PowerShell 窗口**：

| 窗口标题 | 作用 | 监听地址 |
|---|---|---|
| 模型管理平台-后端(勿关) | Flask 后端 | http://127.0.0.1:5000 |
| 模型管理平台-前端(勿关) | Vite 前端 | http://localhost:8080 |

**这两个窗口都不能关**，关了服务就停了。最小化就行。

脚本会先启动后端，**轮询 `/health` 直到它真的响应了**（最多等 30 秒），再拉起前端 ——
这样能避免前端首屏请求全部 404。

等前端窗口出现这样一行，就说明好了：

```
  ➜  Local:   http://localhost:8080/
```

然后浏览器访问 **http://localhost:8080**。

## 5. 常见问题排查

| 现象 | 原因 | 怎么处理 |
|---|---|---|
| `python` 不是内部或外部命令 | 装 Python 时没勾 PATH | 重装 Python 并勾选 `Add python.exe to PATH` |
| 01 脚本报「找不到满足要求的版本」 | Python 不是 3.12.x | 本包 wheel 是 cp312 的，换成 Python 3.12 |
| 02 脚本报「无法连接到 MySQL」 | MySQL 服务没启动 | 管理员命令行执行 `net start MySQL` |
| `db.env` 密码与实际不符 | 装 MySQL 时设了别的密码 | 改 `db.env` 里的 `MODEL_DB_PASSWORD` |
| 前端窗口报 `vite 不是内部或外部命令` | `node_modules` 没拷过去 | 复制 `03-前端离线依赖\node_modules` 到前端目录 |
| 访问 8080 打不开，但 5173 能开 | `.env.development` 缺 `VITE_PORT = 8080` | 手动加这一行，重启前端 |
| 登录后页面空白 / 一直转圈 | 后端没起来或端口不对 | 访问 `/health` 确认后端，检查 `.env.development` 的 `VITE_API_URL` |
| 控制台报 `非标准返回：[object Object]` | 业务接口走了框架的信封校验 | 确认页面用的是 `utils/platformRequest.ts` |
| 推理报「模型产物缺失」(409) | 该模型还没训练过 | 在「模型管理-训练」里点一次「开始训练」 |
| 前端很卡、切页面几秒 | `main.ts` 里加了整页刷新（开发用） | 属预期行为，不必处理 |
| 后端窗口看着像卡住不动 | TensorFlow 首次导入要 20~40 秒 | 等一会儿，属正常 |
| 脚本提示「禁止运行脚本」 | PowerShell 执行策略限制 | 用 `run.bat 0X` 运行，或加 `-ExecutionPolicy Bypass` |
| 中文乱码 | 命令行编码不是 UTF-8 | 脚本已自带设置；手工执行时先敲 `chcp 65001` |
| **登录报 `Table 'model_management.Users' doesn't exist`** | **没跑鉴权迁移 SQL** | **见 `升级到单端口版-迁移指南.md` 第 3 步** |
| **访问根路径看到一坨 JSON 接口清单** | **前端产物没构建/没找到** | 跑 `npm run build -- --mode singleport`，或把 dist 放到 `data\web` |
| **打开是「后端已启动，但还没有前端页面」** | **找不到前端产物** | 同上。这个提示页本身就是后端在工作正常的证据 |
| **页面能开但接口全 404** | **前端产物是用旧模式构建的（指向 5000）** | 重新 `npm run build -- --mode singleport` |
| **刷新页面变 404 白页** | **SPA 兜底没生效（代码未更新全）** | 确认 `model_service/web.py` 存在且 `main.py` 里调用了 `register_frontend` |
| **重启服务后所有人都掉线** | **`MODEL_SECRET_KEY` 没配** | 见迁移指南第 4 步 |
| **服务起不来** | **数据库连不上 / 端口被占** | 看 `data\logs\service-err.log` |
| **局域网别的电脑连不上** | **防火墙没放行 8080** | `New-NetFirewallRule -DisplayName '模型管理平台' -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow` |

## 附录 A：为什么不能直接复制 venv

这是离线部署最容易踩的坑，值得单独讲一下。

你可能会想：「`venv` 里不就是一堆 Python 包吗？直接拷过去不就省了装依赖？」

**不行，而且拷过去会坏得很隐蔽。** 原因是 `venv` 里到处写死了本机的绝对路径：

**① `venv\pyvenv.cfg`** —— 记录了 Python 解释器的位置：

```ini
home = C:\Users\a1507\AppData\Local\Programs\Python\Python312
executable = C:\Users\a1507\AppData\Local\Programs\Python\Python312\python.exe
```

**② `venv\Scripts\activate.bat`** —— 写死了虚拟环境位置：

```bat
set VIRTUAL_ENV=D:\HUAT\22project\testRestfulProject\venv
```

**③ 最关键的一点**：`venv\Scripts\python.exe` 只有 **264 KB**，它**不是真正的 Python**，
只是一个**跳板**，靠 `pyvenv.cfg` 里的 `home` 去找真正的解释器。

所以拷到实验室电脑上时：

- 如果那台电脑**没装** Python → 跳板找不到解释器，`python.exe` 直接报错
- 如果那台电脑装了 Python 但**装在别的路径** → 同样找不到，还是报错
- 就算路径碰巧一样，`venv` 里 `.pth` 文件、脚本 shebang 也都是绝对路径

**正确做法**就是本手册第 1 步：在实验室电脑上 `python -m venv venv` 新建一个，
再用本地 wheel 装依赖。这样 `pyvenv.cfg` 里写的是**那台电脑自己的** Python 路径，一切正常。

> 这也是为什么 `04-项目源码\testRestfulProject\` 里**故意不含 `venv`** —— 不是打包时漏了，是有意排除的。

### torch 的特殊处理

- `requirements.txt` 里保留了这一行（如实反映需要的版本）
- 但安装时要配合 `--index-url https://download.pytorch.org/whl/cpu`，

- `requirements.txt` 文件头已经写明了正确做法

### 离线清单是怎么生成的

## 附录 C：部署脚本为什么是 `.ps1` 而不是 `.bat`

一开始这几个脚本是写成 `.bat` 的，但在测试时发现**中文批处理在 `cmd.exe` 下极不可靠**，
最后全部改成了 PowerShell（`.ps1`）。原因值得记一笔：

**根本问题**：`cmd.exe` 解析 `.bat` 时，**完全不管文件本身是什么编码**，
它一律按**系统 ANSI 代码页**去解码（中文 Windows 上是 GBK/936）。

于是用 UTF-8 保存的中文批处理会出现：

1. 中文注释变成乱码
2. 更糟的是，乱码片段会被 `cmd.exe` 当成**命令**去执行，报出一堆
   `'某某' 不是内部或外部命令`
3. 如果乱码里包含 `"` 或 `(` `)`，**整行的语句结构会被破坏**，
   连 `if ... (` 这样的基本语法都解析不了

实测时甚至出现了「`set "STEP=%~1"` 这一行无法执行」的情况 —— 只是因为文件里有中文。

**为什么 PowerShell 没这个问题**：`powershell.exe` 读取 `.ps1` 时会正确识别 UTF-8，
中文正常显示，语法也不会被破坏。所以：

- 真正的逻辑全部写在 `.ps1` 里（含中文提示，编码 UTF-8）
- `.bat` 只留一个 `run.bat` 做入口转发，且**内容纯 ASCII**，
  这样它自己不会有编码问题

**给后来维护者的忠告**：如果你要改这些脚本，**改 `.ps1` 就好，不要往 `run.bat` 里加中文**。
一旦 `run.bat` 里出现中文，上面那些诡异报错就会回来。

> 类似的坑：项目里 `frontend` 的 `.env.development` 被 gitignore 排除导致端口回落 5173，
> 也属于「换个环境就失效」的问题。离线部署的难度往往不在技术本身，
> 而在这些**环境假设**上。
