# 代码更新流程（改完代码之后怎么同步到实验室电脑）

> **一句话回答**：不用重新配置，**只拷代码**就行，通常几 MB、一分钟搞定。
> 环境（Python / Node.js / MySQL / VC++ / venv / node_modules）装一次就不用再动。

---

## 核心认知：实验室电脑上的东西分两类

| 类别 | 具体是什么 | 改代码之后要动吗 |
|---|---|---|
| **① 环境** | Python、Node.js、MySQL、VC++ 运行库 | ❌ **永不再装** |
| | `testRestfulProject\venv`（Python 依赖） | ❌ **永不重装** |
| | `frontend\22project\node_modules`（前端依赖） | ❌ **永不重装** |
| **② 代码** | `.py` / `.vue` / `.ts` / `.html` / `.sql` / 配置 | ✅ **只需覆盖这些** |

**90% 的日常改动（改功能、改界面、改接口）都只涉及 ②，也就是拷几 MB 的文件。**

---

## 标准流程（三步）

### 第 1 步：在笔记本上生成更新包

运行：

```
tools\make-update-package.ps1
```

（右键 →「使用 PowerShell 运行」，或命令行
`powershell -ExecutionPolicy Bypass -File "tools\make-update-package.ps1"`）

它会自动生成一个 `code-update-<时间戳>\` 文件夹，里面：

- ✅ 后端代码（`testRestfulProject` 下所有 `.py`、`sql/`、`requirements.txt` 等）
- ✅ 前端代码（`frontend/22project/src` 全部 + 配置文件）
- ✅ **前端构建产物 `dist`**（必须带！否则前端改动到不了实验室，见下方警告）
- ✅ `应用更新.ps1`（一键应用脚本，免得你忘记带）
- ❌ **不含** `venv`（几十 MB 且不用重装）
- ❌ **不含** `node_modules`（45,304 个文件且不用重装）
- ❌ **不含** `db.env`（实验室的数据库密码可能与本机不同）
- ❌ **不含** `.mat` 数据集（几十 MB 且几乎不变）
- ❌ **不含** `data/models/` 模型产物（见下方说明）
- ❌ **不含** 日志、图、发布包（运行期产物）

> **实测体积：约 16 MB（含 `dist`，453 个文件）**

> ⚠️ **为什么必须带上 `dist`**
> 实验室机器上跑的是 `npm run build` 出来的**静态产物**，不是源码。
> 只覆盖 `src/*.ts`、不覆盖 `dist`，浏览器加载的还是旧 JS ——
> 表现为「代码明明改了、页面还是老样子」，而且极难排查。
> 所以打包脚本会连 `dist` 一起放进包里，覆盖后立即生效，
> 实验室机器**不需要装 Node、也不需要重新 build**。

> ⚠️ **前端产物统一放 `frontend\22project\dist`，不要用 `data\web`**
> 后端两个位置都会探测（见 `web.py` 的 `_dist_dir()`），但 `应用更新.ps1` **只覆盖 `frontend\22project\dist`**。
> 如果你把产物放到 `data\web`，更新包就覆盖不到它，后端会一直读旧产物。

> ⚠️ **为什么模型产物不进更新包**
> `data/models/` 里是"模型在**哪台机器**上训出来的就归哪台机器"。带上它的后果是：
> 实验室上次辛苦训好的模型，会被笔记本上的版本**静默覆盖**；而且 `meta.json`
> 里还留着笔记本的绝对路径（`D:\HUAT\22project\...`），看日志时很费解。
>
> **如果你确实想把本机模型同步过去**（比如你重训出一个更好的），
> 不要改脚本，单独拷 `data\models\<模型名>\` 覆盖过去就行。

### 第 2 步：拷到实验室电脑

优盘、网线、微信传文件都行 —— 因为只有几 MB，比第一次部署轻松太多。

### 第 3 步：在实验室电脑上应用

**先把后端和前端那两个窗口关掉**（若已装服务，则 `net stop ModelPlatform`），
然后运行更新包里的：

```
应用更新.ps1
```

它会自动：

1. 找到实验室电脑上的项目目录（找不到会提示你手动指定）
2. **检查服务是否已停止**（防止文件被占用）
3. **备份**即将被覆盖的代码（出问题能回滚）
4. 覆盖代码 **（含前端构建产物 `dist`）**
5. **完整性检查**：
   - `venv` 还在吗
   - 新代码能不能正常 `import`（能立刻发现语法错误）
   - `db.env` 有没有被误覆盖
   - `node_modules` 还在吗

然后启动服务：`net start ModelPlatform`，
浏览器打开 `http://<IP>:8080`，**按 `Ctrl + F5` 强制刷新一次**。

## 两个脚本的关系

```
笔记本                                          实验室电脑
────────                                        ──────────
make-update-package.ps1
        │
        ├─ 生成 code-update-<时间戳>/
        │     ├─ testRestfulProject/          ← 后端代码
        │     ├─ frontend/22project/src/      ← 前端源码
        │     ├─ frontend/22project/dist/     ← 前端构建产物（关键！）
        │     └─ 应用更新.ps1                 ← 一起放进去
        │
        └─────── 优盘（约 16 MB）───────────────►  应用更新.ps1
                                                        │
                                                        ├─ 备份
                                                        ├─ 覆盖（含 dist）
                                                        └─ 自检
```

> `apply-update.ps1`（源文件在 `tools\` 下）可以平时就放在项目里，
> 打包时会被自动复制进包内并改名为 **`应用更新.ps1`**，免得你忘记带。

## 什么情况下才需要重装依赖（很少见）

只有**依赖清单变了**才需要 —— 也就是你**新增了第三方库**。

| 情况 | 判断依据 | 怎么处理 |
|---|---|---|
| 后端加了新 pip 包 | `requirements.txt` 变了 | 在笔记本上 `pip download` 新包 → 拷过去 → `pip install --no-index` |
| 前端加了新 npm 包 | `package.json` 变了 | 在笔记本上把更新后的 `node_modules` 拷过去覆盖 |
| **只改 `.py` / `.vue` / `.ts` 代码** | — | ✅ **什么都不用重装** |

### 后端加依赖的具体做法

假设你加了 `requests` 之外的某个库，比如 `openpyxl`：

```powershell
# 笔记本上：把新包下载到"新增依赖"目录
cd D:\HUAT\22project\testRestfulProject
venv\Scripts\python.exe -m pip download openpyxl -d D:\HUAT\22project\offline_package\02-Python离线依赖 --only-binary=:all:

# 拷到实验室电脑后：
cd <实验室项目目录>\testRestfulProject
venv\Scripts\python.exe -m pip install --no-index --find-links="<离线依赖目录>" openpyxl
```

### 前端加依赖的具体做法

```powershell
# 笔记本上：装好新包
cd D:\HUAT\22project\frontend\22project
npm install <新包名>

# 把 node_modules 重新拷到实验室电脑覆盖（45,304 个文件，用 robocopy 快）
robocopy "D:\HUAT\22project\frontend\22project\node_modules" ^
         "<实验室>\frontend\22project\node_modules" ^
         /E /MT:16
```

## 用 Git 会不会更省事？

**会更省事，但有个前提**：实验室电脑得能访问到你的代码仓库。

如果实验室那台电脑**永远不联网**，Git 就用不了，只能靠优盘 —— 也就是上面这套流程。
但即使是优盘流程，也建议**先在笔记本上 `git commit`**，这样：

- 有版本记录，改坏了能回退
- 两台笔记本（你和队友）之间能同步
- 老师要看代码时有完整历史

### 如果实验室电脑能连局域网

那可以更进一步 —— 把笔记本做成 Git 服务，实验室电脑直接 `git pull`：

```powershell
# 笔记本上：把仓库共享出来
cd D:\HUAT\22project
git daemon --base-path=. --export-all --reuseaddr --port=9418
```

```powershell
# 实验室电脑上：一次性配置，之后每次 git pull 即可
git clone git://<笔记本IP>:9418/ 项目
# 以后更新就是：
git pull
```

不过**最简单的还是优盘 + 上面那两个脚本**，不用配网络，出问题也好排查。

## 常见疑问

**Q：改了代码，实验室电脑上的模型会丢吗？**
A：不会，而且**这正是把 `data/models/` 排除在更新包之外的原因**。
实验室电脑上训出来的模型保留在它自己的 `data/models/` 里，更新代码不会碰它。

**Q：那如果我在笔记本上重训了一个更好的模型，怎么弄过去？**
A：单独拷，不要走更新包（更新包已经把 `data/models/` 排除了）：

```powershell
robocopy "D:\HUAT\22project\testRestfulProject\data\models\1dcnn" ^
         "<实验室>\testRestfulProject\data\models\1dcnn" /E
```

拷完重启后端即可。⚠️ 注意 `meta.json` 里会记着笔记本的路径，
那只是"当初用哪个数据集训的"的记录，不影响推理，但显示出来会有点怪。

**Q：数据库要重建吗？**
A：不用。表结构没变就不用动数据库。只有改了 `sql/schema_mysql.sql`
（加字段、加表）才需要执行对应的 ALTER 语句。

**Q：覆盖错了、系统跑不起来怎么办？**
A：`应用更新.ps1` 每次都会先备份，路径会打印在屏幕上（形如
`D:\模型管理平台-离线部署包\04-项目源码\..\_backup-<时间戳>`）。
把它里面的内容覆盖回去就恢复了。

**Q：两个人各改各的，怎么合？**
A：**这一步建议用 Git**（在能联网的笔记本之间同步）。
优盘流程适合"单向更新"：笔记本 → 实验室电脑，不适合双向合并。
