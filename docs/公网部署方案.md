# 发布到公网 · 步骤与安全加固方案

> 面向本项目的**公网部署**（不只是内网）。文档按"能不能、怎么做、必须补什么"三层写。
> 配套模板：`docs/公网部署/nginx-model-platform.conf`、`docs/公网部署/Caddyfile`。

---

## 0. 先决定：真的要开公网吗？（强烈建议先看这一段）

本平台当前形态是**内网工具**：无登录限速、默认允许自助注册、无 HTTPS、训练同步阻塞单进程。
如果使用者只是"实验室/车间/同事几十人"，**下面这些方案比开公网更安全也更省事**：

| 方案 | 适用 | 优点 | 代价 |
|---|---|---|---|
| **只在内网跑**（现状） | 同一局域网 | 零暴露面 | 出差/在家用不了 |
| **VPN**（WireGuard / OpenVPN / 校园 VPN） | 固定一群人 | 只需开 VPN 端口，平台仍只听内网 | 每人要装 VPN |
| **组网工具**（ZeroTier / Tailscale / 蒲公英） | 小团队、跨地点 | 配置极简，做二层内网 | 依赖第三方 |
| **内网穿透**（frp / Cloudflare Tunnel） | 临时演示给别人看 | 不用公网 IP、可加 Cloudflare 的 WAF | 依赖第三方或自建 frp 服务器 |
| **真正公网**（本文档 1~8 节） | 对外提供服务 | 谁都能访问 | **必须做完全部加固**，否则等于把机器交出去 |

> 判断标准：**使用者是不特定的人、要开放注册、要对外宣传** → 才需要公网；
> 否则优先 VPN / 组网工具。

## 1. 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| 服务器 | Linux（Ubuntu 22.04 / 24.04 首选） | **不建议用 Windows 做公网入口**；本平台的 Windows 服务方式适合内网 |
| 配置 | 最低 2 核 4G；要训练建议 4 核 8G+ | 深度学习吃内存：实测加载 tensorflow 后常驻 ~500MB，训练峰值再涨；磁盘 ≥ 40G（venv 2.7G + 数据） |
| 公网 IP / 域名 | 一个域名（例：`ai.example.com`） | HTTPS 证书要域名，不要用 IP 裸跑 |
| **ICP 备案**（中国大陆服务器） | **必须** | 域名解析到大陆服务器对外 HTTP(S) 服务**必须先备案**，否则会被拦截；不想备案就用香港/境外服务器 |
| 安全组/防火墙 | 只放行 **80、443**（+ 你的 SSH 端口） | 8080/3306 **一律不要**对公网开放 |

## 2. 服务器与系统准备

```bash
# 2.1 系统更新 + 基础工具
sudo apt update && sudo apt -y upgrade
sudo apt -y install git curl ufw fail2ban

# 2.2 建一个专用用户（不要用 root 跑服务）
sudo adduser --disabled-password --gecos "" modelapp
sudo usermod -aG sudo modelapp

# 2.3 SSH 加固：密钥登录 + 禁密码 + 禁 root 直登（改完先另开一个窗口验证还能登录！）
sudo sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/'            /etc/ssh/sshd_config
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo systemctl restart ssh

# 2.4 防火墙：只开 22 / 80 / 443
sudo ufw default deny incoming && sudo ufw default allow outgoing
sudo ufw allow 22/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
sudo ufw enable
```

## 3. 部署本平台（一条命令）

```bash
sudo -iu modelapp                       # 用专用用户
git clone https://github.com/lijiaxing748-afk/22project.git
cd 22project
sudo bash start.sh                      # 自动：Python 3.12(缺则装) → 依赖 → MySQL(缺则装) → 建库+专用账号
                                        #       → 写 db.env(含随机密钥) → 建表 → 前端 → systemd 开机自启
```

完成后**先只在服务器本机自测**（此时还没对外）：

```bash
curl -s http://127.0.0.1:8080/health        # 期望 {"status":"ok",...}
sudo bash start.sh status                    # 服务状态
```

> ⚠️ 别急着把 8080 开到公网 —— 第 4 节的反向代理负责对外，8080 永远只听本机。

**必须先做的两件事**（第 5 节有完整清单）：

1. 用初始账号 `admin / Admin@2026` 登录，**立刻改口令**（`MODEL_BOOTSTRAP_ADMIN_PASSWORD` 只在首次建账号时生效）；
2. 编辑 `testRestfulProject/db.env`，加上公网需要的开关（见 5.2），然后 `sudo bash start.sh` 重启生效。

## 4. 反向代理 + HTTPS

### 方案 A：Caddy（推荐，自动申请并续期证书）

```bash
sudo apt -y install debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt -y install caddy
sudo cp docs/公网部署/Caddyfile /etc/caddy/Caddyfile     # 把里面域名改成你的
sudo nano /etc/caddy/Caddyfile                           # 改 ai.example.com → 你的域名
sudo systemctl reload caddy
```

### 方案 B：nginx + certbot

```bash
sudo apt -y install nginx certbot python3-certbot-nginx
sudo cp docs/公网部署/nginx-model-platform.conf /etc/nginx/conf.d/model-platform.conf
sudo nano /etc/nginx/conf.d/model-platform.conf           # 改 server_name
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d ai.example.com                     # 自动改配置 + 自动续期
```

**反代里必须注意的 3 个点**（模板里已写好，照抄即可）：

| 项 | 值 | 为什么 |
|---|---|---|
| `client_max_body_size` | `512m` | 平台上传模型上限 **500MB**、数据集 300MB；不改默认 1m 会直接 **413** |
| `proxy_read_timeout` / `proxy_send_timeout` | `1800s` | **训练是同步接口**，一次训练可能几分钟到几十分钟，默认 60s 会被掐断 |
| 安全响应头 | `X-Frame-Options`、`X-Content-Type-Options`、`Referrer-Policy`、HSTS | 应用本身**没有**输出安全头（实测代码里没有） |

## 5. 安全加固清单（**公网必做**）

### 5.1 应用层

| 项 | 怎么做 | 现状 |
|---|---|---|
| 改默认管理员口令 | 登录后改；或建库前设 `MODEL_BOOTSTRAP_ADMIN_PASSWORD=<强口令>` 再初始化 | ⚠️ 默认 `admin/Admin@2026` |
| **关闭自助注册** | `db.env` 加 `MODEL_ALLOW_REGISTER=0` | ⚠️ **默认是打开的** |
| 打开登录验证码 | `db.env` 加 `MODEL_CAPTCHA=1` | 默认关闭 |
| 缩短令牌有效期 | `MODEL_TOKEN_TTL_HOURS=8`（默认 12） | 默认 12 小时 |
| 确认秘钥是随机的 | `db.env` 里 `MODEL_SECRET_KEY` 应为 64 位十六进制 | 部署脚本会自动生成 ✓ |
| **绝不打开鉴权绕过** | 确保 `db.env` 里**没有** `MODEL_AUTH_DISABLED=1` | 默认关闭 ✓ |
| 不允许加载不可信 pickle | 不要设 `MODEL_ALLOW_UNTRUSTED_PICKLE=1` | 默认禁止 ✓ |
| 登录失败限速 | 应用**没有**失败计数/锁定（实测），靠 **fail2ban + nginx 限速**补（见 5.2/5.3） | ❌ 缺失 |

改完后重启生效：`sudo bash start.sh`（不会覆盖你改过的 `db.env`）。

### 5.2 fail2ban：封暴力破解

```ini
# /etc/fail2ban/jail.d/model-platform.local
[model-platform]
enabled  = true
port     = http,https
filter   = model-platform
logpath  = /var/log/nginx/access.log
maxretry = 10
findtime = 600
bantime  = 3600
```

```ini
# /etc/fail2ban/filter.d/model-platform.conf
[Definition]
failregex = ^<HOST> .* "POST /api/login/ HTTP/[0-9.]+" 40[13] .*$
ignoreregex =
```

```bash
sudo systemctl restart fail2ban && sudo fail2ban-client status model-platform
```

### 5.3 nginx 限速（模板里已含）

`limit_req_zone` + 对 `/api/login/` 单独更严的限速，能大幅抬高爆破成本。

### 5.4 系统与数据

| 项 | 做法 |
|---|---|
| MySQL 只听本机 | 部署脚本装的是本地库；确认 `bind-address = 127.0.0.1`，3306 不对公网开放 |
| 用非 root 跑服务 | `start.sh` 生成的 systemd 单元已经用当前 sudo 用户；别改成 root |
| 数据库账号最小权限 | 部署脚本自动建的 `model_app` 只授权本库 —— 别图省事换成 root |
| 备份 | `mysqldump`（每日）+ `data/` 目录（模型/图片/导出）打包；**存到另一台机器** |
| 恢复演练 | **上线前必须完整恢复一次**，否则备份等于没有 |
| 日志轮转 | systemd 用 journald（`journalctl -u model-platform`）；nginx 日志配 `logrotate` |

## 6. 本平台的架构限制（决定"公网能撑多大"）

| 限制 | 说明 | 影响 |
|---|---|---|
| **只能单进程** | 进程级 `redirect_stdout` + 进程内 `threading.Lock`（建表串行化） | **不能多实例水平扩展**；多开实例会互相踩日志与建表 |
| **训练接口是同步的** | 没有任务队列（实测无 Thread/Queue/subprocess 调度） | 一次训练占住一个 waitress 线程（默认 6 个）；**同时 6 个长训练就会把线程池占满**，别人请求排队 |
| 推理/训练吃 CPU/内存 | 加载 tensorflow 后常驻约 500MB | 小服务器 + 多人同时点训练 → 内存/CPU 打满 |
| 无登录失败锁定 | 应用层没有 | 靠 fail2ban/nginx 限速兜 |
| 无安全响应头 | 应用层没有 | 靠反代补 |
| 上传上限 | 模型 500MB、数据集单文件 80MB/整批 300MB | 反代必须放宽到 ≥512MB |

**结论**：适合"**几十人、可信用户、偶尔训练**"的规模；
如果是"**对公众开放注册、多人高频训练**"，正确做法是先做**架构拆分**：
`API 进程（可多实例）+ 任务队列（Celery/RQ）+ 训练 worker（按 GPU/CPU 数）`，把训练从请求线程里拿出来。
这个改造不小，建议在内网/VPN 阶段先跑顺、确有需求再做。

## 7. 上线后运维

```bash
sudo bash start.sh status            # 服务状态
sudo bash start.sh logs              # 跟日志
sudo bash update.sh                  # 更新到仓库最新代码（拉取 → 重建前端 → 重启）
sudo bash start.sh uninstall         # 彻底下线（之后可删目录）
```

- 备份脚本示例（放 crontab，每天 3 点）：

```bash
0 3 * * * mysqldump -u model_app -p"$(grep ^MODEL_DB_PASSWORD /opt/22project/testRestfulProject/db.env | cut -d= -f2)" \
          model_management | gzip > /backup/db-$(date +\%F).sql.gz
15 3 * * * tar czf /backup/data-$(date +\%F).tgz -C /opt/22project/testRestfulProject data
```

- 监控：外部用 Uptime Kuma / 阿里云监控探测 `https://域名/health`；内部看 `journalctl`。

## 8. 合规（中国大陆）

| 项 | 说明 |
|---|---|
| **ICP 备案** | 域名解析到**大陆**服务器提供网站服务必须备案（在云厂商控制台办，一般 1~20 个工作日） |
| 公安联网备案 | 备案通过后 30 日内到全国互联网安全管理服务平台登记 |
| 等保（可选） | 若属于单位信息系统，按单位要求做等保定级备案 |
| 不想备案 | 用香港/新加坡等境外服务器（无需 ICP，但延迟高、部分网络不稳） |

## 9. 一页速查（公网最小落地方案）

```
服务器(Ubuntu 24.04, 4C8G) + 域名(已备案)
  → ufw 只开 22/80/443，SSH 改密钥登录
  → sudo bash start.sh                        # 一键部署（Python/MySQL 缺就自动装）
  → 本机 curl 127.0.0.1:8080/health 通过
  → Caddy 或 nginx 反代 + Let's Encrypt 证书（client_max_body_size 512m；超时 1800s；补安全头）
  → db.env: MODEL_ALLOW_REGISTER=0, MODEL_CAPTCHA=1, MODEL_TOKEN_TTL_HOURS=8
  → 登录后立刻改 admin 口令；确认 MODEL_AUTH_DISABLED 未设置
  → fail2ban 封登录爆破 + nginx 限速
  → 每日 mysqldump + data 备份，并完整恢复演练一次
  → 上线；用 update.sh 更新，用 start.sh uninstall 下线
```

> ⚠️ 一句话：**别把 8080 直接开到公网**。对外只开 443，其余全走反向代理。
